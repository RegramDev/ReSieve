# 1.1.0 评估记录

本版对应 Regram b34660，内部模型版本 `2026-11-16.10`。采用第 37 阶段、第 2 个 epoch 的权重，推广阈值为 `0.99164`。输入、分窗和类别顺序见[推理说明](inference.md)。

## 文字分类

| 检查 | 结果 | 怎样理解 |
| --- | --- | --- |
| 公开验证文字 7,003 条 | TP 876、FP 13、FN 2,614、TN 3,500；precision 98.54%，recall 25.10%，正常类 FPR 0.37% | 用于选择阈值，不能再当作独立测试集 |
| 公开历史基准 6,663 条 | TP 928、FP 23、FN 2,464、TN 3,248；precision 97.58%，recall 27.36%，正常类 FPR 0.70% | 已在多轮开发中反复测量；垃圾信息标签与本项目的商业推广政策并不完全一致 |
| 人工编写的域内验证 55 条 | 正常 30/30 保留，推广 21/25 识别 | 参与检查点和阈值选择 |
| 外部机器人开发用例 87 条 | 正常 48/48 保留，推广 9/39 识别 | 只测文字分数，未直接用这些原文训练；开发中已多次查看 |

本版并非每项指标都提高。相比 1.0.0，公开历史基准的正常误判率从 0.95% 降到 0.70%，召回从 33.34% 降到 27.36%；外部机器人用例的正常误判从 1 条变为 0 条，识别的推广从 16/39 降为 9/39。选择这版时优先减少正常内容被删的情况。

## Regram 显示回归

这里检查的是模型和客户端共同处理后的消息，不能算作模型单独的成绩。

- 939 条开发消息中，813 条包含正常文字，本轮未发现正常文字误删；689 条包含广告文字，本轮未发现已标注广告片段残留。
- 125/125 条纯广告隐藏，575/575 条混合消息按标注保留正常内容并完整移除广告，按钮检查未发现错误。
- 本轮用户指定的 8 条消息全部隐藏，未使用个人纠错覆盖这些例子。
- 另有 4 条个人媒体纠错单独统计，不能据此声称模型认识图片中的广告。

计数会重叠。这些例子包含训练难例、人工对照和重复模板，不是新的随机样本；“零残留”只描述这一组回归。只删除联系方式、仍留下推广正文的结果按失败处理。

## 导出一致性

同一检查点导出了 FP32 PyTorch 和 FP16 Core ML 权重。100 个转换输入的最大概率差为 `0.004074990749359131`，通过小于 `0.01` 的验收；另有 12 个长文本窗口边界检查。原生 Core ML 与导出参考概率的最大差为 0。仓库文件的重新加载检查使用 `local_files_only=True` 和 `CPU_ONLY`，不下载基础模型。

版本、文件摘要和来源在 [model.json](../model.json)、[provenance.json](../metadata/provenance.json) 和 [SHA256SUMS](../SHA256SUMS) 中。权重与 b34660 应用使用的源模型一致。

## 边界

这仍是中文文字分类器。它不读取图片像素、视频或音频，也没有测得未知频道广告的整体覆盖率。客户端会额外保护正常正文、引用和代码，并处理广告链接、按钮及媒体；直接用单个分数删除整条消息会得到不同结果。

训练使用了经过审阅的本机例子和人工对照。原文、标注、划分和优化器状态不在仓库中，因此这里能离线推理，不能完整复现训练。新包的真机内存、温度、续航和滚动表现还需要实测。
